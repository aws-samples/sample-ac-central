## Quick Start

| Step | Action | Command |
|------|--------|---------|
| 1 | Install CLI | `npm install -g @aws/agentcore` |
| 2 | Create Agent | `agentcore create` |
| 3 | Add SDK | `uv add bedrock-agentcore strands-agents` |
| 4 | Develop Locally | `agentcore dev` |
| 5 | Deploy | `agentcore deploy` |

## Your Journey to Production

From first API call to enterprise deployment in five stages.

1. **Build Your Agent** — Use any framework (Strands, LangGraph, CrewAI, Claude Agent SDK). Test locally with `agentcore dev`.
2. **Add Identity & Auth** — Configure OAuth 2.0 token exchange with your corporate IdP.
3. **Connect Tools via Gateway** — Register internal APIs, databases, and SaaS integrations.
4. **Deploy & Scale** — Push to AgentCore Runtime with `agentcore deploy`. No Kubernetes needed.
5. **Monitor & Iterate** — Track every conversation with OpenTelemetry-based tracing via CloudWatch.

## Recommended Patterns for Conversational Agents

AgentCore supports [12 multi-agent patterns](/patterns/overview). The ones below are the most common starting points for chat workloads.

| Pattern | When to Use | Example |
|---------|-------------|---------|
| **Single Agent + Tools** | Single domain, fewer than 10 tools, straightforward flows | [BGL — NL-to-SQL](https://aws.amazon.com/blogs/machine-learning/democratizing-business-intelligence-bgls-journey-with-claude-agent-sdk-and-amazon-bedrock-agentcore/) |
| **Agents-as-Tools** | Multi-domain support, complex routing | [Thomson Reuters](https://aws.amazon.com/blogs/machine-learning/how-thomson-reuters-built-an-agentic-platform-engineering-hub-with-amazon-bedrock-agentcore/) |
| **Graph (Intent Router)** | Structured flows with conditional branching | [Iberdrola](https://aws.amazon.com/blogs/machine-learning/iberdrola-enhances-it-operations-using-amazon-bedrock-agentcore/) |
| **Human-in-the-Loop** | Regulated industries, high-stakes decisions | [Thomson Reuters](https://aws.amazon.com/blogs/machine-learning/how-thomson-reuters-built-an-agentic-platform-engineering-hub-with-amazon-bedrock-agentcore/) |

:::info
All AgentCore patterns work for conversational agents. For the full catalog including Swarm, Workflow, A2A, and Plan-Act-Reflect, see the [Architectural Patterns Reference](/patterns/overview).
:::

## Chat-Specific Configuration

The same patterns are used across archetypes. What differs is *how you configure AgentCore services* for conversational workloads.

| AgentCore Service | Chat Configuration | Why It Matters |
|-------------------|--------------------|----------------|
| **Identity** | End-user OAuth token exchange (Entra ID, Okta, Cognito) | Agent acts *on behalf of the user* |
| **Memory** | Session + long-term, namespace per user | Multi-turn context + cross-session recall |
| **Runtime** | Streaming enabled, session affinity, up to 8h sessions | Real-time UX, stateful conversations |
| **Guardrails** | Content filters + topic boundaries + PII redaction | Adversarial inputs (prompt injection, social engineering) |
| **Observability** | Per-conversation tracing with user context | Debug "the agent gave me wrong info" |
| **Gateway** | User-scoped tool access with auth propagation | Agent calls APIs as the user |
