# Adopt AgentCore with an Existing Agent

## Choose this path when

You are a developer migrating an existing agent to AgentCore Runtime. Your agent code already works — in Strands, LangGraph, CrewAI, or a custom framework — and you want to adopt AgentCore services incrementally without a full rewrite.

## What it produces

Your agent runs on AgentCore using the custom-agent interface, with microVM isolation, scale-to-zero billing, and OpenTelemetry tracing — without rewriting your orchestration logic.

## Start with the canonical tutorial

Follow the [Custom agent deployment guide](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/getting-started-custom.html) to deploy your existing agent code to AgentCore Runtime using the custom-agent interface.

**Choose an alternative when:**

Use the [CLI Python tutorial](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli.html) if you are building a new agent rather than adapting an existing one.

## What Central adds

Central provides the decision framework and incremental adoption guidance that the canonical tutorial does not cover:

- **Assess container compatibility** — determine whether your agent's dependencies, runtime version, and network requirements are compatible with AgentCore Runtime's microVM environment
- **Add the AgentCore Runtime dependency** — integrate the `bedrock-agentcore` SDK into your existing project and wrap your entry point with `BedrockAgentCoreApp`
- **Update the entry point** — replace your agent's current request-handling interface with the `@app.entrypoint` decorator; for most frameworks this is a thin wrapper around the framework's own invocation pattern
- **Deploy via the custom-agent interface** — use the custom-agent deployment path rather than the standard scaffold flow, preserving your existing project structure
- **Framework and migration trade-offs** — no full agent rewrite is required; the custom-agent interface accepts any Python callable, so Strands, LangGraph, CrewAI, and custom frameworks all work with a thin adapter layer

## Prototype and readiness boundary

:::caution Prototype boundary
**Prototype boundary:** This path is a prototype until you have applied the controls in [Preparing for production](/docs/operate/production-readiness). Do not use a prototype endpoint to serve real user traffic.
:::
