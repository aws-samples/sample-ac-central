# Your First Agent with Managed Harness

This is the Managed Harness path. You define your agent through the console or the `CreateHarness` API; AgentCore wires together Runtime, Memory, Gateway, Browser Tool, Identity, and Observability for you. No orchestration code required.

**Choose this path when:** you want a fully managed, production-grade agent loop, prefer a console or API-first workflow, or want to run agents without maintaining orchestration code.

**If you are building a new custom agent and want full code control from day one**, use the [Code-First Runtime path](/docs/get-started/quickstart) instead.

Before you start, complete the [Preflight Checklist](/docs/get-started/preflight).

This guide has two parts:

1. **[Part 1: Test in the console](#part-1-test-in-the-console)** — create and test an agent in the AgentCore console playground, no local tools required
2. **[Part 2: Create the agent with the AgentCore CLI](#part-2-create-the-agent-with-the-agentcore-cli)** — build the same agent as a declarative project you can version, review, and deploy from your terminal

---

## What Managed Harness does

The Harness is a managed abstraction that lets you create a working agent without writing Python or TypeScript. Under the hood it provisions and connects:

- **AgentCore Runtime**: microVM-isolated execution with scale-to-zero
- **Memory**: session and user memory with a toggle; no persistence code to write
- **Gateway**: tool federation via MCP for attaching external APIs and built-in tools
- **Identity**: OAuth/OIDC integration for user-scoped tool access
- **Observability**: tracing enabled by default, visible in CloudWatch

You interact with the Harness through the AgentCore console wizard, the AgentCore CLI, or directly through the `CreateHarness` and `InvokeHarness` APIs. The configuration is declarative; changing a model or adding a tool does not require redeploying code.

**Export path:** when your use case grows beyond what Harness configuration supports, you can export the agent definition to code and move to the Runtime path. There is no lock-in.

## Part 1: Test in the console

The console is the fastest way to see a Harness agent working. You only need an AWS account and console access.

<div className="fancy-table fancy-table--auto-first">

| Step | Action | Details |
|---|---|---|
| 1 | **Open the AgentCore console** | Navigate to the Amazon Bedrock AgentCore console in your AWS account and choose **Quick create Harness** |
| 2 | **Create an agent** | Use the guided wizard to define your agent: select a model, write a system prompt, and choose tools to attach |
| 3 | **Configure tools** | Connect to APIs via AgentCore Gateway (MCP), or add built-in tools such as Code Interpreter or Browser Tool |
| 4 | **Test in the console playground** | Send test prompts using sample or synthetic data to verify the agent behaves as expected |

</div>

:::note
Step 4 creates a working prototype. Do not route real user traffic to this prototype without completing the [Production Readiness checklist](/docs/operate/production-readiness) first. The checklist covers IAM scoping, tenant isolation, guardrails, evaluations, and rollback procedures.
:::

### Key capabilities available from the console

- **Identity integration**: attach an OAuth provider to enable user-scoped tool access
- **Memory**: enable session memory (short-term) and user memory (long-term) with a toggle
- **Guardrails**: add content filters, topic boundaries, and PII redaction from the console
- **Observability**: tracing enabled by default; view in CloudWatch or export via OTLP

When the agent behaves the way you want in the playground, move to Part 2 to recreate it as a project you can put under version control and deploy repeatably.

## Part 2: Create the agent with the AgentCore CLI

The console is great for interactive testing, but production agents belong in version control. In this part you define the same kind of agent as a declarative project with the AgentCore CLI: `harness.json` describes the agent, and the CLI deploys it through CloudFormation.

**Prerequisites:** Node.js 20+ and AWS credentials configured locally (`aws sts get-caller-identity` should succeed). See the [Preflight Checklist](/docs/get-started/preflight).

:::caution Creates real AWS resources
Deploying creates a harness, an IAM execution role, and CloudWatch log groups in your account, and each invocation calls the configured Bedrock model. The [cleanup step](#step-5-clean-up) removes everything.
:::

### Step 1: Create the project and add a harness

Run this from the directory where you want the project folder created:

```bash
npm install -g @aws/agentcore@0.24.1
agentcore create --project-name firstagent --no-agent
cd firstagent
agentcore add harness \
  --name FirstAgent \
  --model-provider bedrock \
  --system-prompt "You are a helpful assistant that answers questions about cloud computing. Be concise and accurate. If you don't know something, say so."
```

The project now contains:

```text
firstagent/
├── agentcore/                 # Project config and CDK deployment project
│   └── agentcore.json
└── app/FirstAgent/            # Harness definition (configuration, not code)
    ├── harness.json
    └── system-prompt.md
```

There is no `main.py`. The agent loop is managed by AgentCore.

### Step 2: Review and validate the configuration

The `add harness` command wrote the full agent definition to `app/FirstAgent/harness.json`:

```json
{
  "name": "FirstAgent",
  "model": {
    "provider": "bedrock",
    "modelId": "global.anthropic.claude-sonnet-4-6"
  },
  "systemPrompt": "You are a helpful assistant that answers questions about cloud computing. Be concise and accurate. If you don't know something, say so.",
  "tools": [],
  "skills": [],
  "memory": {
    "mode": "disabled"
  }
}
```

This is the whole agent: model, prompt, tools, and memory in one reviewable file. Long-term memory is disabled by default; to add managed per-user memory, follow the [Harness Quick Start](/docs/workloads/conversational/harness-quickstart).

Validate the configuration:

```bash
agentcore validate
# Expected: Valid
```

### Step 3: Deploy

```bash
agentcore deploy
```

Review the confirmation prompt before continuing (use `--yes` in CI). The CLI synthesizes a CloudFormation stack (`AgentCore-firstagent-default`) and deploys the harness, its IAM execution role, and log groups. When it finishes, the outputs include the harness ARN and `Status: READY`. Confirm with:

```bash
agentcore status
# Expected: FirstAgent: Deployed (v1)
```

### Step 4: Invoke the agent

Session IDs must be at least 33 characters; a UUID satisfies this. Reuse the same ID to continue a conversation:

```bash
SESSION_ID="$(uuidgen)"

agentcore invoke --harness FirstAgent \
  --session-id "$SESSION_ID" \
  "What is scale-to-zero and why does it matter for agent workloads?"

agentcore invoke --harness FirstAgent \
  --session-id "$SESSION_ID" \
  "Summarize your previous answer in one sentence."
# Expected: a one-sentence summary — the harness kept the session context across turns.
```

The second response confirms the managed loop maintains conversation history within a session, with no session-handling code on your side.

### Step 5: Clean up

Remove the harness from the project configuration and apply the empty state:

```bash
# From your project directory; review the confirmation prompt before continuing
agentcore remove all
agentcore deploy
```

This tears down the CloudFormation stack. Verify:

```bash
agentcore status
# Expected: No resources match the given filters.
```

CloudWatch log groups are retained; delete them manually to stop log storage charges.

## When to move to code

Harness runs production agents at scale. Move to the Code-First Runtime path when your requirements call for code-level control:

- You need custom tool logic that cannot be expressed in Gateway configuration
- You want to integrate complex routing or multi-step orchestration
- You want your agent logic itself under unit test in your language of choice

To move, export your Harness agent definition (`agentcore export` or from the console) and use it as the starting point for a code-first project.
