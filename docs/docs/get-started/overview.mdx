# Get Started with AgentCore

## Choose this path when

You are deciding which AgentCore getting-started path fits your goal. You might be a first-time agent builder evaluating managed vs. code-first approaches, or an experienced developer migrating an existing agent onto AgentCore Runtime.

## What it produces

After reading this page you will understand which Get Started path — Managed Harness, Code-First Runtime, or Existing Agent Adoption — matches your situation, so you can move directly to the right tutorial.

## Start with the canonical tutorial

Begin with the [Harness getting-started guide](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-get-started.html) to deploy a fully managed agent through configuration rather than code. This is the fastest route to a running agent on AgentCore.

**Choose an alternative when:**

Use the [CLI Python tutorial for code-first Runtime prototyping](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli.html) if you want to write agent logic in code rather than configure it in the console.

## What Central adds

- **Path selection logic:** A decision framework that maps your situation (managed vs. code-first vs. migration) to the right canonical tutorial, so you skip paths that do not apply.
- **Prototype-to-production framing:** Each path produces a working prototype; Central clarifies what remains before that prototype can serve real traffic.

## Prototype and readiness boundary

:::caution

**Prototype boundary:** This path is a prototype until you have applied the controls in [Preparing for production](/docs/operate/production-readiness). Do not use a prototype endpoint to serve real user traffic.

:::
