# Preflight Checklist

Before starting any AgentCore getting-started path, work through this checklist. Most items take under five minutes to verify. Skipping them is the most common reason tutorials fail halfway through.

---

## AWS account and region

### Account requirements

- An AWS account you can use for testing. A dedicated development or sandbox account is preferable to a shared account with other workloads.
- Sufficient IAM permissions to create the resources the tutorial will create (see [IAM permissions](#iam-permissions) below).
- If your organization requires it, a Service Control Policy (SCP) review before creating new Bedrock resources.

### Region availability

AgentCore services are not available in every AWS region. Check the [AgentCore Developer Guide](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/) for the current list of supported regions before picking a region to work in. Tutorials on this site default to `us-east-1`; substitute a supported region in your area if needed.

:::warning
If you deploy to a region where a required AgentCore service is not yet available, you will get access or not-found errors that look like permission issues. Verify region support first.
:::

## Bedrock model access

AgentCore agents invoke models through Amazon Bedrock. Bedrock model access is not enabled by default; you must request it per model per account per region.

1. Open the [Amazon Bedrock console](https://console.aws.amazon.com/bedrock/) in your target region.
2. Go to **Model access** in the left navigation.
3. Enable **Anthropic Claude Sonnet** (specifically the model IDs referenced in the tutorial you are following).
4. Wait for the status to change to **Access granted** before proceeding. This usually takes under two minutes but can take longer on first request.

If you do not have model access, agent invocations will fail with an `AccessDeniedException` that points at the model ID.

## IAM permissions

AgentCore tutorials involve two distinct IAM concerns.

### Deployment role

The role you use to run `agentcore deploy` or create resources via the console. It needs permissions to create and manage the AgentCore resources in the tutorial. At minimum:

- `bedrock-agentcore:*` on the resources created in the tutorial
- `iam:PassRole` to associate the runtime execution role with a deployment
- CloudFormation and ECR permissions if using the CDK-backed CLI path
- Permissions to create CloudWatch log groups for observability

The exact policy depends on which services the tutorial creates. The [AgentCore Developer Guide](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/) documents the required permissions per service.

### Runtime execution role

The role AgentCore assumes when running your agent. It is separate from your deployment credentials. It needs:

- `bedrock:InvokeModel` (or `bedrock:InvokeModelWithResponseStream`) for the specific model your agent uses
- Permissions for any AgentCore services your agent calls at runtime (Memory, Gateway, Observability)
- Permissions for any external resources your agent's tools access

Follow least-privilege from the start. Broad policies like `AdministratorAccess` on the runtime execution role give the agent unnecessary access to your account. Scope it to exactly what the agent needs.

## Local development tools

For the [Code-First Runtime path](/docs/get-started/quickstart):

- **Node.js 20 or later**: required by the AgentCore CLI. Check with `node --version`.
- **Python 3.12 or later**: required for the agent runtime. Check with `python3 --version`.
- **uv**: Python package manager used by the CLI scaffolding. [Install guide](https://docs.astral.sh/uv/getting-started/installation/).
- **AWS CLI**: for credential configuration and sanity checks. [Install guide](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html).
- **AWS credentials**: configured with `aws configure`, environment variables, or an IAM role. Run `aws sts get-caller-identity` to confirm they are working.

The [Managed Harness path](/docs/get-started/firstagent) uses the same Node.js and AgentCore CLI setup, but no Python — the agent is configuration, not code.

## Data and security considerations

Before you send real data to a prototype:

- **Use synthetic or sample data in tutorials.** The getting-started guides use simulated weather data and similar placeholders. Do not substitute production customer data, PII, or proprietary information while following tutorials. Prototype environments typically lack the access controls required for sensitive data.
- **Understand what leaves your account.** Requests to Bedrock models are processed within AWS infrastructure. Review the [Bedrock data privacy FAQ](https://aws.amazon.com/bedrock/faqs/) and your organization's data classification policy before processing regulated data.
- **Session context and memory.** If you enable Memory in a tutorial, session context is stored in AgentCore Memory. Understand the retention settings before storing anything sensitive.
- **Logs and traces.** Observability traces include prompt content and tool call parameters by default. If a trace contains sensitive data, scope log retention and access accordingly.

These considerations apply to the tutorials as learning exercises. Before moving any agent toward production traffic, work through the [Production Readiness](/docs/operate/production-readiness) checklist.

## Resources created and cost expectations

The getting-started tutorials create real AWS resources that incur costs. The main cost drivers are:

<div className="fancy-table fancy-table--auto-first">

| Resource | Cost driver | Notes |
|---|---|---|
| Bedrock model invocations | Per-token pricing for input and output | Cost varies by model; Claude Sonnet 4.5 is priced higher than smaller models |
| AgentCore Runtime | Per execution-second and per request | Scale-to-zero means no cost when idle |
| AgentCore Memory | Storage and retrieval operations | Minimal for tutorial volume |
| CloudWatch logs and traces | Ingestion and retention | Usually negligible for tutorial volume |
| ECR (CLI path) | Container image storage | Minimal for tutorial images |

</div>

Tutorial workloads typically cost a few dollars or less at development volume. That said, resources left running do accumulate cost over time.

**Clean up after each tutorial.** Each tutorial includes a cleanup section or links to the resources it creates. Run cleanup before you leave a tutorial behind. The AgentCore CLI path can remove resources with `agentcore destroy` from the project directory. Console-created resources can be deleted through the AgentCore console.
