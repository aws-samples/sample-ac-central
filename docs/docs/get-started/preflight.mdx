# Preflight Checklist

## Choose this path when

You have chosen a Get Started path and need to prepare your AWS account and local environment before running the tutorial.

## What it produces

Your account and environment are ready to run the chosen tutorial without mid-tutorial permission failures, region mismatches, or missing model access.

## Start with the canonical tutorial

Follow the [Runtime getting started prerequisites](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli.html#prerequisites) for the complete upstream prerequisite procedure.

**Choose an alternative when:** Link to a service-specific prerequisites section only when the chosen path requires a service-specific requirement not covered here.

## What Central adds

The following readiness areas apply to every Get Started path on this site. The canonical tutorial covers procedural setup; this section covers the planning and awareness context Central owns.

### Region

AgentCore services are not available in every AWS region. Before choosing a region:

- Check the [AgentCore Developer Guide region availability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html) for the current list of supported regions.
- Tutorials on this site default to `us-east-1`. Substitute a supported region closer to your location if needed.
- If you deploy to a region where a required AgentCore service is not yet available, errors will resemble permission failures rather than region availability issues.

### Least-privilege IAM permissions

AgentCore tutorials involve two IAM roles:

- **Deployment role** — the identity you use to create AgentCore resources. Scope it to `bedrock-agentcore:*` on tutorial resources, `iam:PassRole` for runtime role association, and any CloudFormation or ECR permissions required by your chosen path.
- **Runtime execution role** — the identity AgentCore assumes when running your agent. Scope it to `bedrock:InvokeModel` for the specific model your agent uses, plus permissions for any AgentCore services (Memory, Gateway, Observability) and external resources your agent's tools access.

Follow least-privilege from the start. Broad policies like `AdministratorAccess` on the runtime execution role give the agent unnecessary access to your account. The [AgentCore Developer Guide](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/) documents the required permissions per service.

### Bedrock model access

Not all Bedrock model access is enabled by default. You may need to request it per model, per account, per region [Request access to models](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html).

- Enable the specific model IDs referenced in the tutorial you are following (for example, Anthropic Claude Sonnet).
- Model access requests usually take under two minutes but can take longer on first request.
- Without model access, agent invocations fail with an `AccessDeniedException` referencing the model ID.

### Cost drivers

Tutorial workloads typically cost a few dollars or less at development volume. The main cost drivers are:

| Resource | Cost driver | Notes |
|---|---|---|
| Bedrock model invocations | Per-token pricing for input and output tokens | Cost varies by model; larger models are priced higher |
| AgentCore Runtime | Per execution-second and per invocation request | Scale-to-zero means no cost when idle |
| AgentCore Memory | Storage and retrieval operations (reads/writes) | Minimal at tutorial volume |
| CloudWatch logs and traces | Ingestion and retention | Usually negligible at tutorial volume |

Resources left running accumulate cost over time. Each tutorial includes a cleanup section — run cleanup before you leave a tutorial behind.

### Data residency

- Requests to Bedrock models are processed within AWS infrastructure in the region you select. Review the [Bedrock data protection page](https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html) and your organization's data classification policy before processing regulated data.
- If you enable Memory, session context is stored in AgentCore Memory in the deployment region. Understand retention settings before storing anything sensitive.
- Observability traces include prompt content and tool call parameters by default. If a trace contains sensitive data, scope log retention and access accordingly.

### Security constraints

- Use synthetic or sample data in tutorials. Prototype environments typically lack the access controls required for sensitive data, PII, or proprietary information.
- Do not substitute production customer data while following tutorials.
- If your organization requires it, complete a Service Control Policy (SCP) review before creating new Bedrock resources.
- Confirm that your deployment region's compliance posture meets your organization's requirements before handling regulated workloads.
