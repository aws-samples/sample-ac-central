## Choose this path when

You are a developer who wants the fastest code-first prototype. You prefer working in a terminal, iterating locally, and managing configuration in version control.

## What it produces

You will have a local Python agent running in minutes, tested against a live model, and ready for deployment validation.

## Start with the canonical tutorial

Follow the CLI Python tutorial to scaffold, test, and deploy your first agent from the terminal:

- [Build and deploy a Python agent with the AgentCore CLI](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli.html)

**Choose an alternative when:**

Use CLI TypeScript if your agent codebase is TypeScript:

- [Build and deploy a TypeScript agent with the AgentCore CLI](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli-typescript.html)

## What Central adds

- **Why CLI is fastest code-first:** The CLI path gives you a local dev loop with hot-reload, version-controlled declarative configuration, and a single command to move from prototype to deployed endpoint.
- **Post-tutorial readiness:** After the canonical tutorial succeeds, confirm your endpoint is not publicly exposed and consult the production readiness checklist before serving real traffic.

## Prototype and readiness boundary

:::caution
**Prototype boundary:** This path is a prototype until you have applied the controls in [Preparing for production](/docs/operate/production-readiness). Do not use a prototype endpoint to serve real user traffic.
:::
