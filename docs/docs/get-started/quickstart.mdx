# Build your agents from terminal

Go from zero to a working agent on AgentCore. This guide creates a simple weather agent with one tool, tests it locally, and deploys it, all from the terminal.

| | |
|---|---|
| **Who this is for** | Developers new to AgentCore who want a first working prototype |
| **Time** | ~15 minutes |
| **What you'll build** | A weather agent with one tool, local dev server, and a deployed Runtime endpoint |
| **Safety level** | Creates real AWS resources; uses simulated weather data; no external write actions |

:::info Prerequisites
- **Node.js 20+**: for the AgentCore CLI
- **Python 3.12+**: for the agent runtime
- **uv**: Python package manager ([install guide](https://docs.astral.sh/uv/getting-started/installation/))
- **AWS credentials**: configured with `aws configure` or environment variables
- **Bedrock model access**: Claude Sonnet 4.5 enabled in your AWS account ([enable models](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access-modify.html))
:::

---

## Step 1: Install the CLI

```bash
npm install -g @aws/agentcore
agentcore --version
```

---

## Step 2: Scaffold the Project

```bash
agentcore create --name WeatherAgent --framework Strands \
  --model-provider Bedrock --language Python \
  --memory none --build CodeZip --skip-install
```

`--skip-install` skips both `npm install` (for the CDK project) and `uv sync` (for the agent), so scaffolding finishes in under a second. You'll install dependencies in the next step.

This creates the project structure with `agentcore/agentcore.json` as the declarative config.

---

## Step 3: Install Python Dependencies

```bash
cd WeatherAgent/app/WeatherAgent && uv venv && uv sync && cd ../../..
```

---

## Step 4: Write Your Agent

Replace the scaffolded `WeatherAgent/app/WeatherAgent/main.py` with:

```python
"""Weather agent that answers weather questions using a simple tool."""

import json
import random

from strands import Agent, tool
from bedrock_agentcore.runtime import BedrockAgentCoreApp

app = BedrockAgentCoreApp()
log = app.logger


@tool
def get_weather(city: str) -> dict:
    """Get the current weather for a city.

    Args:
        city: The name of the city to check weather for.

    Returns:
        A dictionary with weather information.
    """
    # Simulated weather data for demo purposes
    conditions = ["sunny", "cloudy", "rainy", "partly cloudy"]
    return {
        "city": city,
        "temperature_celsius": random.randint(15, 35),
        "condition": random.choice(conditions),
        "humidity_percent": random.randint(30, 90),
    }


SYSTEM_PROMPT = """You are a helpful weather assistant. When users ask about
the weather, use the get_weather tool to look up current conditions.
Always include the temperature and conditions in your response."""

agent = Agent(
    model="global.anthropic.claude-sonnet-4-5-20250929-v1:0",
    system_prompt=SYSTEM_PROMPT,
    tools=[get_weather],
)


@app.entrypoint
async def invoke(payload, context):
    """Agent entrypoint, called by AgentCore Runtime on each request."""
    prompt = payload.get("prompt", "Hello!")
    log.info("Invoking agent with prompt: %s", prompt)

    async for event in agent.stream_async(prompt):
        if "event" in event:
            yield event


if __name__ == "__main__":
    app.run()
```

:::info Why streaming?
`app.entrypoint` supports async generators. Yielding raw Strands stream events lets `agentcore dev` and AgentCore Runtime render the response as it's generated instead of waiting for the full answer. This is the same pattern the CLI scaffolds by default.
:::

## Step 5: Test Locally

Start the dev server (needs a real terminal, not a piped/non-interactive shell):

```bash
cd WeatherAgent
agentcore dev
```

This opens a local test page in your browser where you can interact with the agent, inspect traces, and iterate on prompts. Try asking "What is the weather in Seattle?" directly in the test page.

Alternatively, you can invoke the agent from a **second terminal**:

```bash
agentcore dev "What is the weather in Seattle?"
```

Expected output:

```
The weather in Seattle is currently partly cloudy with a temperature
of 22°C and humidity at 65%.
```

:::tip
`agentcore dev` requires an interactive terminal. If you see `No agents defined in project` even though `agentcore validate` says your config is valid, you're likely running it through a pipe or a non-TTY shell. Run it directly in Terminal.app, iTerm, or your IDE's integrated terminal.
:::

---

## Step 6: Deploy to AgentCore

Install the CDK project dependencies:

```bash
cd agentcore/cdk && npm install && cd ../..
```

Run a dry run first to preview what will be created without deploying:

```bash
agentcore deploy --dry-run
```

When you're satisfied with the plan, deploy:

```bash
agentcore deploy
```

Once deployed, invoke the live agent:

```bash
agentcore invoke "What is the weather in Tokyo?"
```

That's it. Your agent is deployed to a live AgentCore Runtime endpoint with:
- **MicroVM isolation**: each session in a dedicated sandbox
- **Scale-to-zero**: no idle cost when there are no requests
- **OpenTelemetry tracing**: full observability via CloudWatch

## What's in `agentcore/agentcore.json`

The CLI generated this configuration for your agent:

```json
{
  "name": "WeatherAgent",
  "version": 1,
  "managedBy": "CDK",
  "runtimes": [
    {
      "name": "WeatherAgent",
      "build": "CodeZip",
      "entrypoint": "main.py",
      "codeLocation": "app/WeatherAgent/",
      "runtimeVersion": "PYTHON_3_13",
      "networkMode": "PUBLIC",
      "protocol": "HTTP"
    }
  ],
  "memories": [],
  "credentials": []
}
```

This is the declarative source of truth for your AgentCore resources. As you add Memory, Gateway, or credentials via `agentcore add`, they appear as new entries under `runtimes`, `memories`, `agentCoreGateways`, and so on.

:::info Runtime version
The CLI may scaffold `runtimeVersion: "PYTHON_3_14"` (a pre-release version). Change it to `"PYTHON_3_13"` before deploying.
:::

## What This Creates and What It Costs

Deploying this quickstart creates the following AWS resources:

| Resource | Notes |
|---|---|
| AgentCore Runtime | Hosts your agent code in MicroVM isolation |
| ECR repository | Stores the packaged agent image |
| IAM execution role | Least-privilege role for the Runtime |
| CloudWatch log group | Receives runtime and invocation logs |

**Main cost drivers:**
- **Model inference tokens** — every invocation calls Claude Sonnet 4.5 on Amazon Bedrock; you pay per input/output token
- **Runtime execution seconds** — billed per second of agent execution; scale-to-zero means no charges between invocations
- **Log ingestion** — CloudWatch charges per GB of logs ingested and stored

**Scale-to-zero does not mean zero cost.** Even with no traffic, the ECR image and CloudWatch log retention continue to accrue charges. Destroy the resources when you're done experimenting (see Cleanup below).

---

## Cleanup

When you are done with this prototype, destroy the AWS resources it created:

```bash
# From the WeatherAgent project directory
agentcore destroy
```

Verify resources are gone:

```bash
agentcore status
# Expected: no runtimes listed
```

Some resources may persist after `agentcore destroy`:

- **ECR repository** — may remain if images are still tagged; delete manually in the ECR console or with `aws ecr delete-repository --repository-name WeatherAgent --force`
- **CloudWatch log groups** — retained by default; delete manually if you want to stop log storage charges
- **IAM roles** — review and remove any leftover roles prefixed with `AgentCore` in the IAM console

If `agentcore destroy` reports errors, see [Cleanup Failures](/docs/reference/troubleshooting#cleanup-failures).
