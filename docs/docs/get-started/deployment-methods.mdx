## Choose this path when

You are a developer choosing between CLI, console, direct code, or infrastructure-as-code to deploy your agent. You want to understand which deployment method fits your stack and operational requirements.

## What it produces

You will understand which deployment method fits your stack, including trade-offs around local tooling, container control, and declarative lifecycle management.

## Start with the canonical tutorial

Follow the CLI Python tutorial to deploy your first agent using the recommended default path:

- [Build and deploy a Python agent with the AgentCore CLI](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli.html)

**Choose an alternative when:**

Use CLI TypeScript if your agent codebase is TypeScript:

- [Build and deploy a TypeScript agent with the AgentCore CLI (TypeScript)](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli-typescript.html)

Use the console path if you prefer a UI-led experience without local tooling:

- [Create and deploy an agent in the console](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/create-deploy-agent.html)

Use direct code deployment if you need full container control with a custom runtime:

- [Deploy an agent with direct code deployment](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-code-deploy.html)

Use CloudFormation if you need declarative infrastructure-as-code lifecycle management:

- [CloudFormation AgentCore resource types](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/AWS_BedrockAgentCore.html)

## What Central adds

The decision matrix below maps each deployment method to the criteria that matter when choosing your approach. Each row links to its verified canonical implementation — no runnable steps are included here.

| Method | Local vs. CI/CD tooling | Container control | Declarative lifecycle | Canonical source |
|---|---|---|---|---|
| CLI | Local dev loop with hot-reload; single-command deploy | Managed by CLI scaffolding | CLI-generated CDK stack; ejectable | [CLI Python tutorial](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli.html) |
| Console/manual | No local tooling required; browser-based | Managed by the service | Console-driven; no template files | [Create and deploy in the console](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/create-deploy-agent.html) |
| Direct code | Full CI/CD integration; bring your own build | Full container ownership; custom base image | Programmatic via API or SDK | [Direct code deployment](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-code-deploy.html) |
| IaC | CI/CD pipeline with change review; GitOps-compatible | Defined in template; reproducible | Full declarative lifecycle via CloudFormation or CDK | [CloudFormation AgentCore types](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/AWS_BedrockAgentCore.html) |
