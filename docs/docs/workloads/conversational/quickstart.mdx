## Identity Management

- Every conversational agent must propagate end-user identity. Use OAuth bearer tokens from your IdP (Entra ID, Okta, Cognito) so the agent acts **as the user**, not as a shared service account. See [Understanding workload identities](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/understanding-agent-identities.html) for how this fits AgentCore's identity model.
- Memory is namespaced by `actor_id` — never share one actor ID across multiple users, or their conversations will bleed together. See [Per-user memory scoping with actor ID](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-memory.html).
- Validate caller-supplied identity headers against a verified source (JWT claims from AgentCore Identity or your own auth layer) before production use. The [JWT-based identification pattern](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/get-workload-access-token.html) is recommended for production; the [JWT inbound + OAuth outbound sample](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-oauth.html) shows the full end-to-end flow.

## Session Continuity

- Configure both short-term (in-session) and long-term (cross-session) [memory strategies](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-types.html) so the agent remembers context within a conversation and user preferences across sessions.
- Use unique session IDs per conversation. Reuse a session ID only when you want to resume the same conversation thread. See [Memory organization](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-organization.html) for how strategy/actor/session namespaces work.
- Plan context window strategies (summarization, truncation) for long conversations that approach model limits. AgentCore Memory supports [namespace-scoped long-term storage](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/specify-long-term-memory-organization.html) to retain summaries across sessions without exhausting the context window.

## Safe First-Deployment Patterns

- Deploy with scale-to-zero to avoid charges when idle, but remember that Memory records and CloudWatch logs still accrue cost. Review the [Runtime lifecycle settings](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-lifecycle-settings.html) for idle timeout defaults and configurable values.
- Start with the default model and tools; add capabilities incrementally after validating each works correctly.
- Use [`agentcore dev`](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli.html) for local iteration before deploying to AWS — local testing verifies agent logic without incurring cloud costs.
- Review the [Production Readiness checklist](/docs/operate/production-readiness) before routing real users. Note that [CLI-generated IAM policies are not suitable for production](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-security-best-practices.html) — create scoped custom policies before serving real traffic.

## Resource and Cost Awareness

<div className="fancy-table">

| Cost Driver | What Generates It | How to Manage |
|---|---|---|
| Model inference tokens | Every invocation calls the configured LLM; multi-turn conversations multiply token usage | Choose model size for your task; monitor token usage; use summarization strategies to avoid replaying full history |
| Memory — short-term | $0.25 per 1,000 new events ingested | Set `eventExpiryDuration`; clean up test data |
| Memory — long-term storage | $0.75 per 1,000 records stored/month (built-in strategies) | Scope retention policies; delete prototype memory resources |
| Memory — long-term retrieval | $0.50 per 1,000 retrievals | Retrieve only when needed; avoid unnecessary recall on every turn |
| Gateway invocations | Each tool call via Gateway is $0.005 per 1,000 invocations | Batch tool calls where possible; cache results for repeated lookups |
| Policy authorization | $0.000025 per request + $0.13 per 1,000 input tokens processed | Negligible at tutorial volume; monitor at scale |
| Runtime execution (CPU + memory) | $0.0895/vCPU-hour + $0.00945/GB-hour while the session is active | Scale-to-zero; set idle session timeouts; avoid long-lived idle sessions |
| Identity token requests | $0.010 per 1,000 token requests (free when used through Runtime or Gateway) | Typically no cost for standard conversational flows |
| Log ingestion | CloudWatch charges per GB for spans, logs, and metrics | Set retention policies; filter verbose output |

</div>

Scale-to-zero does not mean zero cost. Memory records and log retention continue to accrue charges even with no active traffic. Remove prototype resources when done experimenting. See [AgentCore pricing](https://aws.amazon.com/bedrock/agentcore/pricing/) for current rates.

Everything produced by the samples on this page is a prototype until you have applied the controls in [Preparing for production](/docs/operate/production-readiness). Do not use a prototype endpoint to serve real user traffic.
:::
