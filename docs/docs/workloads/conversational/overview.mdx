# Conversational Agents

Human-initiated chat agents that respond in real-time with multi-turn memory, enterprise identity, and streaming. AgentCore handles the platform complexity so you focus on the agent's intelligence.

---

## What Is It?

A conversational agent is a chat-based AI that interacts directly with humans. Users type messages, the agent reasons and responds, optionally calling tools along the way. Unlike traditional chatbots with scripted flows, conversational agents on AgentCore use LLM reasoning to handle open-ended queries, maintain context across turns, and take actions on behalf of the user.

---

## Common Use Cases

- **Customer support / helpdesk** — End-users ask questions about their account, orders, or services. The agent retrieves information, executes actions (refunds, resets), and escalates to humans when needed.
- **Internal knowledge assistant** — Employees ask HR, IT, or policy questions. The agent searches internal knowledge bases and answers with auth-scoped, role-appropriate responses.
- **Sales co-pilot / deal desk** — Sales reps get real-time guidance during customer calls. The agent pulls CRM data, pricing rules, and competitive intel on demand.
- **NL-to-SQL / self-serve analytics** — Business users ask questions in plain English. The agent translates to SQL, runs the query, and returns results with charts or summaries.
- **Onboarding concierge** — New customers or employees are guided through multi-step setup processes with personalized, context-aware assistance.
- **Technical troubleshooting** — Developers or IT staff describe issues. The agent correlates logs, suggests fixes, and can execute diagnostic commands.

---

## When to Choose Conversational

Choose this workload when:

- A human is the primary trigger (they type a message)
- The agent needs to respond in real-time with token-by-token streaming
- Multi-turn conversation state matters (the agent should remember what was said)
- The agent acts on behalf of a specific user with their identity and permissions
- The primary output is natural language directed at a human

For a side-by-side comparison with Workflow and Coding patterns, see the [Workloads overview comparison table](/docs/workloads/overview#how-they-compare).

## Strengths and Design Considerations

<div className="fancy-table">

| Strengths                                            | Design Considerations                                                        |
|------------------------------------------------------|--------------------------------------------------------------------|
| Real-time streaming for responsive UX                | Plan for per-session cost; use scale-to-zero and session timeouts to manage spend |
| Multi-turn memory with session + long-term recall    | Long conversations need context window strategies (summarization, truncation) |
| End-user identity propagation (zero-trust)           | Requires IdP integration (Entra ID, Okta, Cognito) — plan this early         |
| Natural fit for human-facing applications            | Human-facing surface needs input guardrails (content filters, prompt boundaries) |
| Rich UI feedback (typing indicators, tool activity)  | Session affinity means scaling per user; size infrastructure accordingly      |

</div>

## AgentCore Configuration Summary

<div className="fancy-table fancy-table--auto-first">

| Purpose | Description | AgentCore capability |
|---------|-------------|---------------------|
| **User authentication** | End-user OAuth bearer tokens (Entra ID, Okta, Cognito) so the agent acts on behalf of the user | Identity |
| **Conversation context** | Session memory + long-term recall, namespaced per user for multi-turn continuity and cross-session personalization | Memory |
| **Execution environment** | Streaming-enabled runtime with session affinity and up to 8h lifecycle ¹ for real-time, stateful conversations | Runtime |
| **Input safety** | Content filters, topic boundaries, and PII redaction to protect against adversarial or off-topic inputs | Guardrails (via policy on gateway) |
| **Quality measurement** | GoalSuccessRate, Helpfulness, and Correctness evaluations to catch regressions before users feel them | Evaluations |
| **Debugging and tracing** | Per-conversation traces with user context to diagnose "the agent gave me wrong info" | Observability |
| **Tool access** | User-scoped API access with auth propagation so the agent calls external services as the user | Gateway |

</div>

> ¹ Session duration is architecture guidance based on typical AgentCore usage patterns. Verify current limits in the [Amazon Bedrock AgentCore Developer Guide](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/).

## When Not to Use This Pattern

**Skip the Conversational pattern when:**

- There is no human in the loop. If an event (alert, webhook, file upload) triggers the agent and results go to a downstream system, the [Workflow pattern](/docs/workloads/workflow/overview) is a better fit — it is designed for machine-to-machine automation and costs less at scale.
- The task produces code or structured file artifacts. Use the [Coding pattern](/docs/workloads/coding/overview) instead.
- Interaction is single-turn and stateless. A simple API call to an LLM (with no memory or session state) is often enough — an AWS Lambda function calling the Bedrock InvokeModel API may be all you need, without the overhead of a persistent agent runtime.
- You cannot integrate an identity provider. This pattern depends on user identity propagation (OAuth bearer tokens). If your deployment has no IdP, consider the Workflow pattern with service credentials.
