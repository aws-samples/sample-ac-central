# Conversational Agents

:::tip Who this is for
Developers evaluating whether a conversational workload fits their use case, or looking for the right entry point into building a chat agent on AgentCore. If you've already decided and want to start coding, jump to the [Quick Start](/docs/workloads/conversational/quickstart) or [Harness Quick Start](/docs/workloads/conversational/harness-quickstart).
:::

Human-initiated chat agents that respond in real-time with [multi-turn memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-types.html), [enterprise identity](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html), and [streaming](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-http-protocol-contract.html). AgentCore handles the platform complexity so you focus on the agent's intelligence.

---

## What Is It?

A conversational agent is a chat-based AI that interacts directly with humans. Users type messages, the agent reasons and responds, optionally calling tools along the way. Unlike traditional chatbots with scripted flows, conversational agents on AgentCore use LLM reasoning to handle open-ended queries, maintain context across turns, and take actions on behalf of the user. See [How AgentCore Runtime works](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-how-it-works.html) for the underlying execution model.

---

## Common Use Cases

- **Customer support / helpdesk** — End-users ask questions about their account, orders, or services. The agent retrieves information, executes actions (refunds, resets), and escalates to humans when needed.
- **Internal knowledge assistant** — Employees ask HR, IT, or policy questions. The agent searches internal knowledge bases and answers with auth-scoped, role-appropriate responses.
- **Sales co-pilot / deal desk** — Sales reps get real-time guidance during customer calls. The agent pulls CRM data, pricing rules, and competitive intel on demand.
- **NL-to-SQL / self-serve analytics** — Business users ask questions in plain English. The agent translates to SQL, runs the query, and returns results with charts or summaries.
- **Onboarding concierge** — New customers or employees are guided through multi-step setup processes with personalized, context-aware assistance.
- **Technical troubleshooting** — Developers or IT staff describe issues. The agent correlates logs, suggests fixes, and can execute diagnostic commands.

---

## When to Choose Conversational

Choose this workload when:

- A human is the primary trigger (they type a message)
- The agent needs to respond in real-time with token-by-token [streaming](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-http-protocol-contract.html)
- Multi-turn conversation state matters (the agent should remember what was said)
- The agent acts on behalf of a specific user with their identity and permissions
- The primary output is natural language directed at a human

For a side-by-side comparison with Workflow and Coding patterns, see the [Workloads overview comparison table](/docs/workloads/overview#how-they-compare).

## Strengths and Design Considerations

<div className="fancy-table">

| Strengths                                            | Design Considerations                                                        |
|------------------------------------------------------|--------------------------------------------------------------------|
| Real-time streaming for responsive UX                | Plan for per-session cost; use [scale-to-zero](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-lifecycle-settings.html) and session timeouts to manage spend |
| Multi-turn memory with session + long-term recall    | Long conversations need [context window strategies](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-types.html) (summarization, truncation) |
| End-user identity propagation (zero-trust)           | Requires IdP integration (Entra ID, Okta, Cognito) — plan this early         |
| Natural fit for human-facing applications            | Human-facing surface needs [input guardrails](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-guardrails-in-policies.html) (content filters, prompt boundaries) |
| Rich UI feedback (typing indicators, tool activity)  | [Session affinity](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-sessions.html) means scaling per user; size infrastructure accordingly      |

</div>

<div className="fancy-table fancy-table--auto-first">

|---------|-------------|---------------------|

| **Input safety** | Content filters, topic boundaries, and PII redaction to protect against adversarial or off-topic inputs | [Guardrails](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-guardrails-in-policies.html) |
| **Quality measurement** | `GoalSuccessRate`, `Helpfulness`, and `Correctness` evaluations to catch regressions before users feel them | [Evaluations](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/how-it-works-evaluations.html) |
| **Debugging and tracing** | Per-conversation traces with user context to diagnose "the agent gave me wrong info" | [Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-configure.html) |
| **Tool access** | User-scoped API access with [auth propagation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/on-behalf-of-token-exchange.html) so the agent calls external services as the user | [Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) |

</div>

## When Not to Use This Pattern

**Skip the Conversational pattern when:**

- There is no human in the loop. If an event (alert, webhook, file upload) triggers the agent and results go to a downstream system, the [Workflow pattern](/docs/workloads/workflow/overview) is a better fit — it is designed for machine-to-machine automation and costs less at scale.
- The task produces code or structured file artifacts. Use the [Coding pattern](/docs/workloads/coding/overview) instead.
- Interaction is single-turn and stateless. A simple API call to an LLM (with no memory or session state) is often enough — an AWS Lambda function calling the [Bedrock InvokeModel API](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-api.html) may be all you need, without the overhead of a persistent agent runtime.
- You cannot integrate an identity provider. This pattern depends on user identity propagation (OAuth bearer tokens). If your deployment has no IdP, consider the Workflow pattern with service credentials. If you have Amazon Cognito, see the [Identity getting started with Cognito](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity-getting-started-cognito.html) tutorial.

## Start Building

The [Conversational Agent Catalog](https://github.com/awslabs/agentcore-samples/tree/main/02-use-cases/01-conversational-agents) is the primary starting point for conversational agent development. It contains maintained samples with identity, memory, and streaming built in.

Scaffold a conversational project from your terminal:

```bash
# Create a harness with memory for multi-turn conversations
agentcore create --name mychatagent --model-provider bedrock
agentcore add memory --name chatmemory --strategies SEMANTIC,SUMMARIZATION

# Test locally (deploys and opens browser test page)
agentcore dev
```

Or choose a sample that matches your use case:

| Use Case | Sample | Key Capability |
|----------|--------|----------------|
| General conversational AI | [Catalog default](https://github.com/awslabs/agentcore-samples/tree/main/02-use-cases/01-conversational-agents) | Identity + Memory + Streaming |
| Auth-scoped helpdesk | [Customer Support Assistant (VPC)](https://github.com/awslabs/agentcore-samples/tree/main/02-use-cases/01-conversational-agents/customer-support-assistant-vpc) | VPC-secured, customer identity propagation |
| Operations collaboration (A2A) | [SRE/A2A Incident Response](https://github.com/awslabs/agentcore-samples/tree/main/02-use-cases/01-conversational-agents/A2A-multi-agent-incident-response) | Multi-agent, operations triage |
| Browser/Evaluations/Optimization | [Market Trends Agent](https://github.com/awslabs/agentcore-samples/tree/main/02-use-cases/01-conversational-agents/market-trends-agent) | Browser use, data gathering, evaluation loops |

:::caution Prototype, not production
These samples create working prototypes. Before routing real users or production data, complete the [Production Readiness checklist](/docs/operate/production-readiness).
