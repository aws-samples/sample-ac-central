# Enterprise Features for Conversational Agents

Use this summary to map AgentCore capabilities to conversational-agent needs. Follow the official links for configuration details.

| Capability | Conversational-Specific Purpose | Key Considerations | Configuration Reference |
| --- | --- | --- | --- |
| Identity | Carries verified end-user context to tools. | Use validated claims; no fallback identities. | [Identity documentation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/) |
| Memory | Retains context and preferences across sessions. | Namespace by user; set retention and deletion boundaries. | [Memory documentation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) |
| Gateway | Connects conversations to MCP tools and APIs. | Apply least privilege; make retries idempotent. | [Gateway documentation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) |

## What makes conversational different

Conversational agents must preserve session state across turns. Resume the correct session, namespace memory by verified user, and define retention and deletion boundaries.

They are latency-sensitive: users wait for replies, so stream progress, bound tool timeouts, and make retries idempotent. User-facing error handling should translate timeouts, policy denials, and unavailable tools into clear next steps instead of stack traces or silent failures.

The identity in a conversation is the end user, not only the agent service principal. Carry verified identity through memory, policy evaluation, and downstream tools so personalization never bypasses access control.
