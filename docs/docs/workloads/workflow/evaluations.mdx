# Evaluations for Workflow Agents

Workflow agents make real decisions with real consequences. You need to know, continuously and not just at launch, whether those decisions are correct. Conversational agents have users who immediately notice bad answers. Workflow agents operate in the background, so bad decisions can compound silently for days before anyone notices.

---

## Built-in Evaluators

AgentCore provides built-in evaluators that score agent behavior against your session telemetry. Trajectory evaluators use **programmatic scoring (no LLM calls, zero token cost)**, while GoalSuccessRate and Correctness use LLM-as-a-Judge.

<div className="fancy-table fancy-table--auto-first">

| Evaluator                 | Level   | Ground Truth Field   | What It Measures                                                       |
|---------------------------|---------|----------------------|------------------------------------------------------------------------|
| GoalSuccessRate           | Session | `assertions`         | Behavior satisfies natural-language assertions (LLM-as-Judge)          |
| Correctness               | Trace   | `expectedResponse`   | Response matches the expected answer (LLM-as-Judge)                    |
| TrajectoryExactOrderMatch | Session | `expectedTrajectory` | Exact tool sequence: same tools, same order, no extras (programmatic) |
| TrajectoryInOrderMatch    | Session | `expectedTrajectory` | Expected tools appear in order; extras allowed between (programmatic)  |
| TrajectoryAnyOrderMatch   | Session | `expectedTrajectory` | All expected tools present, any order, extras allowed (programmatic)   |
| Custom (LLM-as-judge)     | —       | placeholders         | Your domain-specific criteria (e.g., "followed escalation policy")     |

</div>

---

## Ground Truth Evaluations

Ground truth is the known-correct answer or expected behavior for a given input. It is the "gold standard" you compare actual results against. You provide reference inputs alongside session spans when calling the Evaluate API, and the service scores actual behavior against expected behavior.

<div className="fancy-table fancy-table--auto-first">

| Field                | Scope   | Description                                                        |
|----------------------|---------|--------------------------------------------------------------------|
| `expectedResponse`   | Trace   | Expected agent response for a specific turn (scoped by `traceId`)  |
| `assertions`         | Session | Natural-language statements that should be true about the behavior |
| `expectedTrajectory` | Session | Expected sequence of tool-call names for the session               |

</div>

Ground truth fields are optional. If you omit them, evaluators fall back to their ground-truth-free mode. For workflow agents, build a benchmark dataset of past events with known-correct outcomes to catch regressions before they reach production.

:::info Prerequisites
Evaluations require an agent deployed on AgentCore Runtime with observability enabled (or a supported framework like Strands Agents or LangGraph configured for AgentCore Observability), **Transaction Search enabled in CloudWatch**, and Python 3.10+.
:::

## Running an Evaluation

Use the AgentCore SDK (or the `agentcore run eval` CLI) to evaluate a session against ground truth:

```python
from bedrock_agentcore.evaluation import EvaluationClient, ReferenceInputs

client = EvaluationClient(region_name=REGION)

results = client.run(
    evaluator_ids=[
        "Builtin.GoalSuccessRate",
        "Builtin.TrajectoryExactOrderMatch",
    ],
    agent_id=AGENT_ID,
    session_id=SESSION_ID,
    reference_inputs=ReferenceInputs(
        assertions=[
            "Agent used the remediation tool for the HIGH-priority incident",
            "Agent did not call any destructive infrastructure tools",
        ],
        expected_trajectory=["get_incident_details", "restart_service"],
    ),
)

for r in results:
    print(f"{r['evaluatorId']}: {r['value']} ({r['label']})")
```

:::tip Cost-efficient quality gates
Trajectory evaluators are programmatic (zero token cost), so you can run them on 100% of invocations cheaply. Reserve the LLM-judged evaluators (GoalSuccessRate, Correctness) for sampled traffic or high-priority events.
:::
