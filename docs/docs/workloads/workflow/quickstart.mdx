# Quick Start: Workflow Agent

Deploy a working event-driven incident response agent in under 10 minutes.

| | |
|---|---|
| **Who this is for** | Developers building event-driven or automation agents |
| **Time** | ~10 minutes |
| **What you'll build** | An incident response agent that enriches, reasons, and creates tickets |
| **Safety level** | Creates real AWS resources; uses simulated service health and ticketing data; no external write actions |

<div className="fancy-table fancy-table--auto-first">

### Create the project and agent

Run this command from the directory where you want the project folder to be created. The explicit names ensure the generated paths match the rest of this quickstart: `incidentagent/app/IncidentAgent/main.py`.

```bash
npm install -g @aws/agentcore@0.24.1
agentcore create \
  --name IncidentAgent \
  --project-name incidentagent \
  --framework Strands \
  --model-provider Bedrock \
  --memory none \
  --build CodeZip \
  --language Python \
  --protocol HTTP \
  --network-mode PUBLIC
cd incidentagent
```

The generated project already declares `strands-agents` and `bedrock-agentcore` as dependencies in `app/IncidentAgent/pyproject.toml` and installs them into the project's virtual environment — no separate SDK installation step is needed.

## Complete Working Example

An event-driven incident response agent that follows the 5-step pattern: Trigger → Enrich → Reason → Act → Emit. Copy this into `app/IncidentAgent/main.py`:

```python
"""Event-driven incident response agent - Trigger → Enrich → Reason → Act → Emit."""

import json
import logging

from strands import Agent, tool

from bedrock_agentcore.runtime import BedrockAgentCoreApp

log = logging.getLogger(__name__)
app = BedrockAgentCoreApp()


# --- Tools (Enrich + Act phases) ---


@tool
def get_service_health(service_name: str) -> dict:
    """Check the health status of a service.

    Args:
        service_name: Name of the service to check (e.g., 'checkout-api').

    Returns:
        Service health information including status, error rate, and latency.
    """
    # Replace with real monitoring API in production
    return {
        "status": "success",
        "content": [
            {
                "text": json.dumps(
                    {
                        "service": service_name,
                        "status": "degraded",
                        "error_rate_percent": 12.5,
                        "p99_latency_ms": 2400,
                        "healthy_instances": 2,
                        "total_instances": 4,
                    }
                )
            }
        ],
    }


@tool
def create_incident_ticket(service_name: str, severity: str, summary: str) -> dict:
    """Open an incident ticket in the ticketing system.

    Args:
        service_name: Name of the affected service.
        severity: Incident severity - 'low', 'medium', or 'high'.
        summary: Human-readable description of the issue and recommended action.

    Returns:
        Created ticket ID and a link for the on-call engineer to review.
    """
    log.info("Creating incident ticket for %s [%s]", service_name, severity)
    # Replace with real ticketing API (e.g., Jira, PagerDuty) in production
    ticket_id = f"INC-{abs(hash(service_name + severity)) % 100000:05d}"
    return {
        "status": "success",
        "content": [
            {
                "text": json.dumps(
                    {
                        "ticket_id": ticket_id,
                        "service": service_name,
                        "severity": severity,
                        "summary": summary,
                        "url": f"https://tickets.example.com/{ticket_id}",
                    }
                )
            }
        ],
    }


@tool
def notify_oncall(message: str, severity: str) -> dict:
    """Send a notification to the on-call engineer.

    Args:
        message: Notification message content.
        severity: Alert severity - 'low', 'medium', or 'high'.

    Returns:
        Notification delivery confirmation.
    """
    log.info("Notifying on-call [%s]: %s", severity, message)
    return {
        "status": "success",
        "content": [{"text": f"Notification sent (severity={severity})"}],
    }


# --- System prompt (Reason phase) ---

SYSTEM_PROMPT = """You are an IT incident response agent. When you receive an
incident event, follow this protocol:

1. ENRICH: Use get_service_health to understand the current state.
2. REASON: Analyze the health data and determine the recommended action.
3. ACT: Open an incident ticket with a clear summary and recommendation.
   If critical, also notify on-call.
4. EMIT: Summarize the findings, the ticket created, and any notifications sent.

Rules:
- Always open a ticket so there is an auditable record of the incident.
- Always notify on-call for 'high' severity incidents.
- Include the recommended remediation in the ticket summary so an engineer
  can review and act on it.
- Be concise in your summary - operations teams need quick answers."""


@app.entrypoint
def invoke(payload, context):
    """Agent entrypoint - processes incident events from EventBridge."""
    # The AgentCore CLI wraps invoke text as {"prompt": "<text>"}. When the
    # text is itself a JSON event, unwrap it back into the event payload.
    if "prompt" in payload and "service_name" not in payload:
        prompt_value = payload["prompt"]
        if isinstance(prompt_value, str):
            try:
                parsed = json.loads(prompt_value)
                if isinstance(parsed, dict) and "service_name" in parsed:
                    payload = parsed
            except (json.JSONDecodeError, TypeError):
                pass

    # Build the prompt from the event payload
    if "service_name" in payload:
        prompt = (
            f"Incident received:\n"
            f"- Service: {payload['service_name']}\n"
            f"- Event: {payload.get('event_type', 'unknown')}\n"
            f"- Severity: {payload.get('severity', 'medium')}\n"
            f"- Description: {payload.get('description', 'No description')}\n\n"
            f"Follow the incident response protocol."
        )
    else:
        prompt = payload.get("prompt", "No event received.")

    agent = Agent(
        model="global.anthropic.claude-sonnet-4-5-20250929-v1:0",
        system_prompt=SYSTEM_PROMPT,
        tools=[get_service_health, create_incident_ticket, notify_oncall],
    )

    result = agent(prompt)
    return {"response": result.message}


if __name__ == "__main__":
    app.run()
```

## Test It

### Test locally

```bash
# Terminal 1: start the dev server (non-interactive, logs to stdout)
agentcore dev --logs --no-browser

# Terminal 2: simulate an incident event
agentcore dev '{"service_name": "checkout-api", "event_type": "high_error_rate", "severity": "high", "description": "Error rate exceeded 10% threshold"}'

# Expected: Agent calls get_service_health, sees degraded status,
# opens an incident ticket with a remediation recommendation,
# notifies on-call, and summarizes actions taken.
```

:::tip Port mismatches cause confusing errors
If port `8080` is busy, the dev server automatically shifts to the next free port (watch for `Port 8080 in use, using 8081` in Terminal 1). The Terminal 2 command still targets `8080` by default, so it can silently hit whatever else is listening there. Pass the printed port explicitly: `agentcore dev -p 8081 '<event-json>'`.
:::

### Test the deployed agent

Deployment creates AWS resources and may incur charges:

```bash
agentcore deploy
```

Then invoke the deployed Runtime with the same event. AgentCore requires a session ID of at least 33 characters; a UUID satisfies this:

```bash
agentcore invoke --session-id "$(uuidgen)" \
  '{"service_name": "checkout-api", "event_type": "high_error_rate", "severity": "high", "description": "Error rate exceeded 10% threshold"}'
```

The CLI wraps the argument as `{"prompt": "<text>"}`; the entrypoint's unwrap logic restores the JSON event. Real event sources (EventBridge, SQS) call `InvokeAgentRuntime` with the event as the payload directly — see [Event Processing](/docs/workloads/workflow/event-processing).

## The 5-Step Pattern in Action

```
① TRIGGER  → EventBridge delivers "high_error_rate" event
② ENRICH   → Agent calls get_service_health("checkout-api")
③ REASON   → LLM sees degraded + high severity → decides to open ticket + notify
④ ACT      → Agent calls create_incident_ticket() and notify_oncall()
⑤ EMIT     → Agent returns structured summary of findings and actions taken
```

## Controlled Remediation

This quickstart uses read-only and notification tools deliberately. Before adding write actions such as restarting services, scaling fleets, or modifying configuration, apply the following safeguards:

:::warning Real write actions require production safeguards
- **Least-privilege access** — scope IAM permissions to the exact resources and operations the agent needs.
- **Typed input validation** — validate all tool inputs before calling downstream APIs; reject unexpected values.
- **Idempotency** — design tools so retrying the same action is safe (e.g., restart-if-not-already-running).
- **Policy enforcement** — use Cedar policies to restrict which actions fire under which conditions (priority, time window, resource scope).
- **Explicit approval or escalation** — for high-risk actions, require a human-in-the-loop confirmation step before execution.
- **Retry and dead-letter behavior** — handle transient failures with bounded retries and route unrecoverable events to a dead-letter queue for manual review.
- **Audit logging** — record every tool invocation with its inputs, outputs, and the policy decision that allowed it.

See [Bounded Autonomy](/docs/workloads/workflow/bounded-autonomy) for how Cedar policies enforce these boundaries in production.
:::

## What This Creates and What It Costs

Deploying this quickstart creates the following AWS resources:

| Resource | Notes |
|---|---|
| AgentCore Runtime | Hosts your agent code in MicroVM isolation |
| IAM execution role | Least-privilege role for the Runtime |
| S3 deployment assets | The CodeZip package is staged in the CDK assets bucket |
| CloudWatch log groups | Receives runtime and invocation logs |

**Main cost drivers:**
- **Model inference tokens** — every invocation calls Claude Sonnet 4.5 on Amazon Bedrock; you pay per input/output token
- **Runtime execution seconds** — billed per second of agent execution; scale-to-zero means no charges between invocations
- **Log ingestion** — CloudWatch charges per GB ingested and stored

**Scale-to-zero does not mean zero cost.** Staged deployment assets and CloudWatch log retention continue to accrue charges even with no active traffic. Remove resources when you're done experimenting.

## Cleanup

When you are done with this prototype, remove the resources managed by the project configuration. `agentcore remove all` resets the local AgentCore resource configuration, and the following `agentcore deploy` applies the empty state to AWS:

```bash
# From your agent project directory; review the confirmation prompt before continuing
agentcore remove all
agentcore deploy
```

Verify resources are gone:

```bash
agentcore status
# Expected: no runtimes listed
```

Some resources may persist after cleanup:

- **S3 deployment assets** — packaged CodeZip archives remain in the CDK assets bucket; delete old objects manually if needed
- **CloudWatch log groups** — retained by default; delete manually to stop log storage charges

If cleanup reports errors, see [Cleanup Failures](/docs/reference/troubleshooting#cleanup-failures).
