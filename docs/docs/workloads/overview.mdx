# Choose the right agent workload

AgentCore supports three agent archetypes. Each is optimized for a different interaction model, trigger pattern, and operational profile. Pick the one that matches your use case, then follow its Quick Start to deploy in minutes.

## When to Use Each Workload

<div className="fancy-table">

| Use Case                                    | Workload         | Why This Fits                                                |
|---------------------------------------------|------------------|--------------------------------------------------------------|
| Customer support / helpdesk agent           | Conversational   | Human-initiated, multi-turn, needs memory of prior exchanges |
| Internal knowledge assistant (HR, IT, etc.) | Conversational   | Q&A with employees, auth-scoped answers per user             |
| Sales co-pilot / deal desk assistant        | Conversational   | Real-time advice during live user interactions               |
| NL-to-SQL / self-serve analytics            | Conversational   | User asks a question, agent queries data and responds        |
| Claims processing / adjudication            | Workflow          | Event-triggered, rules-based, needs bounded autonomy         |
| IT incident response / auto-remediation     | Workflow          | Alert fires, agent triages and acts without a human          |
| Document intake and routing                 | Workflow          | Document uploaded → classify → route → notify                |
| Compliance monitoring / drift detection     | Workflow          | Scheduled scan → detect → remediate or escalate              |
| Order fulfillment exception handling        | Workflow          | System event (stuck order) triggers investigation            |
| Email / ticket triage and auto-response     | Workflow          | Inbound message → classify → auto-reply or route             |
| Feature implementation from Jira tickets    | Coding           | Ticket created → agent generates code → PR for review        |
| Automated code review / security scanning   | Coding           | PR opened → agent reviews → comments inline                  |
| Codebase migration / refactoring            | Coding           | Batch task: transform patterns across many files             |
| Test generation from specifications         | Coding           | Spec updated → agent writes/updates test suites              |
| Documentation generation from code          | Coding           | Code merged → agent generates/updates docs                   |

</div>

## How They Compare

<div className="fancy-table fancy-table--auto-first">

| Dimension              | Conversational                         | Workflow                                          | Coding                                   |
|------------------------|----------------------------------------|---------------------------------------------------|------------------------------------------|
| **Trigger**            | User message (human-initiated)         | System event (machine-initiated)                  | Ticket/PR/schedule (machine-initiated)   |
| **Session duration**   | Minutes to hours (multi-turn)          | Seconds to minutes (single invocation)            | Minutes to hours (long-running task)     |
| **Identity model**     | End-user OAuth bearer tokens (acts as user) | Service identity (acts as system)                 | Developer identity (acts as developer)   |
| **Memory**             | Session + long-term per user           | Cross-invocation context per entity               | Project-scoped context                   |
| **Streaming**          | Token-by-token to UI                   | Optional (results go to downstream systems)       | Optional (progress updates to IDE/CI)    |
| **Primary output**     | Natural language response to human     | Actions taken + structured events emitted         | Code artifacts + PR/review comments      |
| **Scaling pattern**    | Concurrent sessions (many users)       | Event throughput (many events per second)         | Concurrent tasks (many repos/PRs)        |
| **Key metrics**        | Helpfulness, Correctness               | GoalSuccessRate, TrajectoryMatch                  | Code quality, test pass rate             |
| **Idle cost**          | Scale-to-zero between sessions         | Scale-to-zero between events                      | Scale-to-zero between tasks              |
| **Compute lifecycle**  | Up to 8 hours (session affinity)       | Up to 15 minutes (short-lived)                    | Up to 8 hours (long-running)             |
| **Guardrails focus**   | Content filters, PII, prompt injection | Tool-level policies (Cedar), bounded autonomy     | Code quality gates, security scanning    |

</div>

## Decision Guide

**Choose Conversational when:**
- A human is typing messages and expecting real-time responses
- You need multi-turn memory and session continuity
- The agent acts on behalf of the end-user (their identity, their permissions)

**Choose Workflow when:**
- A system event triggers the agent (alert, webhook, schedule, file upload)
- The agent needs to make decisions and take actions autonomously
- You need bounded autonomy: the agent should act within defined guardrails, not freely

**Choose Coding when:**
- The output is code, tests, documentation, or PR comments
- Tasks are long-running and involve file system or repository operations
- You need sandbox isolation for code execution and validation
