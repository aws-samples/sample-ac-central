# Architectural Patterns

:::tip Who this is for
Builders choosing a multi-agent topology for their use case. If you already know which pattern fits, see the [Selection Guide](/docs/patterns/selection-guide) for scenario-to-pattern matching. If you haven't deployed anything yet, start with [Get Started](/docs/get-started/overview).
:::

Multi-agent patterns supported by AgentCore and the Strands SDK. Choose based on your use case, complexity, and execution requirements.

---

## Pattern Catalog

12 patterns organized into three tiers based on documentation maturity and production evidence. All are deployable on AgentCore Runtime.

:::info Pattern documentation sources
Tier labels indicate where patterns are documented and evidenced, not their production
readiness. Tier 1 patterns have official documentation in the
[Strands Agents SDK](https://strandsagents.com/docs/user-guide/concepts/multi-agent/multi-agent-patterns/)
and [AgentCore Samples](https://github.com/awslabs/agentcore-samples). Tier 2 patterns
have published customer evidence. Tier 3 patterns are well-known industry patterns
applicable on AgentCore but without specific AgentCore documentation.
:::

### Tier 2 - Production-Proven Patterns (Customer Evidence)

## How Execution Paths Differ

Understanding how each pattern determines its execution path is key to selecting the right one.

<div className="fancy-table">

| Pattern             | Path Determined By                  | Cycles?       | Parallelism? |
| ------------------- | ----------------------------------- | ------------- | ------------ |
| **Graph**           | LLM decision at each node           | Yes           | No           |
| **Swarm**           | Agents autonomously decide handoffs | Yes           | No           |
| **Workflow (DAG)**  | Fixed dependency graph (DAG)        | No            | Yes          |
| **Agents-as-Tools** | Parent agent decides                | Yes (re-call) | Depends      |
| **A2A**             | Peer agents negotiate               | Yes           | Yes          |

</div>
